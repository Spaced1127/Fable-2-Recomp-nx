# run-053 - element-level guard (FIX TEST v2)

Run 052 proved the guard was too narrow. `[gui-guard] #1` skipped
`sub_822358A8` at 53.964, and **3 ms later** the same null page set faulted
from another site: `read of guest 0x00000024`, crash block `E5085770...`.

## The new fault site

The record's `pc` field is again unreliable (`sub_82265A80`, a rect clipper).
Decoding it from the instruction and the frame chain:

- instruction `0xb8624824` is a guest `lwz rX, 0(r4)` with **r4 = 0x24**, not
  `lwz rX, 0x24(r3)`;
- frame `#00 sub_82426ED8+0x170` is the call to `sub_822659E8`, which does
  `addi r4, r31, 36` then calls `sub_82265A80`.

So the null is consumed by the **element rect/blit routine `sub_82426ED8`**:

```
r5  = [[r3+4]+4]        ; element host
r10 = [r5+36]           ; ref-counted wrapper
r9  = [r10+4]           ; CECPlayerControl
r21 = [r9+100]          ; page set (control +0x64)  <- null
bl sub_822659E8(out, r3, r21, ...)   ; r4 = 0 + 36 = 0x24 -> fault
```

`sub_82426ED8` walks the page set (`[r21+8]`, `[r21+24]`, ...) to build the
source rect for every tile, so a null page set means the whole element has
nothing to draw. Guarding one callee could never cover it.

## The fix

`sub_82426ED8` is now hooked: it resolves the same chain on entry and, when the
page set is null, **skips the element as a unit** (`ctx.r3 = 0`, "nothing
drawn") and logs `[gui-guard] element #n skipped`. The earlier
`sub_822358A8` guard stays - it covers the other consumer of the same null.
Both are reads plus an early return; nothing else changes.

tag `m1-fix-053`. Texture uploads stay on, `[gui-phase]` markers stay.

## Reading the result

- No 0x24 violation and alive past 60 s: crash fixed at the element level. The
  `[gui-guard] element` count tells how many elements are skipped per frame -
  high counts mean the page set is still never populated (the `Data\Worlds\`
  registry gap), which is the remaining producer work.
- A different violation: the guard moved the failure again; the new block names
  the next consumer. If that happens a third time, the null is reaching the
  whole element tree and the fix belongs at the update/enumeration level.
- `[gui-phase]` unchanged: `82A492B0` ~2.05 s plus a ~2.2 s gap, still the
  producer lead.
