# run-069 - F1: read the pixels, name the blank

Run 068 proved the 2D copy EXECUTES and lands the pattern (descriptor A:
rowLength 4096 bytes, imageHeight 720 rows, Usage2DEngine tiled; waitIdle 5 ms,
fence signalled, readback 5A5A5A5A). "The copy is the killer" is dead. The
~9.5 s below-guest death is unchanged and stays instrumented, not chased (F2).

## What this build changes

1. **Guest-output readback (the decisive F1 question).** At present **30** and
   **150**, the presenter reads back the exact image the present copy reads from
   (the branch=1 guest target, RGBA8) into a CpuUncached block - submit,
   signalFence, **flush** (kick), bounded 250 ms wait - and prints:
   `[guest-readback] #N WxH: fnv1a=... min=.. max=.. zero=.../... first=[...] grid=[8x8] verdict=...`
   - **BLANK** (one uniform byte value across the whole surface) -> the guest
     never drew into it: the fault is upstream in draw/target binding.
   - **CONTENT** (varying pixels) -> the present copy / swapchain blit is at
     fault.
   - **NEAR-BLANK** -> bytes vary but the grid is uniform; inspect the grid.
   A fence timeout prints NO verdict (pixels not trustworthy).
2. **In-frame upload probe fixed.** Run 068 armed it but death came 240 ms
   later, before any later upload/draw re-checked it. Now the PRESENTER polls it
   every present (`PollFrameUploadProbe`), and the readback block is CpuUncached
   (CpuCached would read the CPU's own dirty 0xAA pre-fill). Expect
   `[upload] frame-path readback (presenter poll): N of the first 32768 bytes
   differ ... LANDED pixels` two presents after upload #1.
3. **Skip-draw census.** The 540/run `no_render_targets` skips are classed from
   the registers: EMPTY (normalized mask 0, no z/stencil - legitimate null draw)
   vs MASKED (claims writes but nothing bound - the blank-output suspect).
   `[skip-census]` every 128 skips; the first MASKED skip gets a full
   `[skip-dump]` (RB_COLOR_INFO[0..3], RB_DEPTH_INFO, RB_SURFACE_INFO,
   RB_COLOR_MASK, RB_COLORCONTROL, RB_DEPTHCONTROL, PA_SC_SCREEN_SCISSOR_TL/BR,
   PA_SC_WINDOW_OFFSET, PA_SU_SC_MODE_CNTL, resolver used-target count).
   rt0 base 0 is a legitimate EDRAM base - the mask, not the base, decides.
4. **Housekeeping (run-068 correction applied).** Poll-give-up replaced by
   bounded waits: the presenter waits the present fence every frame (no
   permanent give-up); mid-frame splits and the resolve list are **flushed**
   after signalFence and waited bounded (fences signal in ~5 ms once kicked);
   the standalone upload fallback flushes too. "Fences never signal" / "copy is
   the killer" / "standalone path dead" deleted from code comments, fence_wait.h
   and the backend doc; descriptor A canonical; the run-065 a-d diagnostic is
   retired (opt-in only).
5. **Death-watch.** `[death-watch]` every 32 presents: uploads so far, present
   cmd slot, heap/GPU memory - the log tail names the last stage at the ~9.5 s
   death.

Nothing gates boot: readbacks are at present 30/150, bounded, on the presenter
thread after the frame's render list is submitted; the probe poll is
non-blocking.
