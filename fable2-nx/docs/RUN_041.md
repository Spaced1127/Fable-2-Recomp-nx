# run-041 - M1 witness run, full-length

Same diagnostic as run 039/040 with one procedural change: **the session must
last at least 6 minutes**. Runs 039/040 were copied about 50 s after boot; the
fault they are meant to catch arrives minutes into the menu, so it never
happened and `rex_crash.log` gained no block (`docs/runs/040/` proves it: the
file is byte-identical to the 039 copy).

The build also adds one line so the log proves which NRO ran. It changes no
behaviour.

Build: SHA-256 `704867F4EFC6D46B57AF592A48E266393CBB7CBD3A182ED728FD54DAFA157D95`
(`H:\Projects\Fable2Port\stage\switch\Fable II\fable_2.nro`).

## 1. Copy to the SD

Close hbmenu's file browser and any running app. Replace `E:` with your SD drive
letter. Copy only these three files - never mirror the folder:

```powershell
$src = "H:\Projects\Fable2Port\stage\switch\Fable II"
$dst = "E:\switch\Fable II"
Copy-Item "$src\fable_2.nro"        "$dst\fable_2.nro"        -Force
Copy-Item "$src\fable_2.toml"       "$dst\fable_2.toml"       -Force
Copy-Item "$src\fable2_config.toml" "$dst\fable2_config.toml" -Force
(Get-FileHash "$dst\fable_2.nro" -Algorithm SHA256).Hash
# must be 704867F4EFC6D46B57AF592A48E266393CBB7CBD3A182ED728FD54DAFA157D95
```

## 2. Clear the old crash report - do this before launching

`logs/rex/rex_crash.log` is append-only and never overwritten, and a stale copy
has already cost two runs. Before this run:

- If `E:\switch\Fable II\logs\rex\rex_crash.log` exists, rename it to
  `rex_crash.pre041.log`.
- Confirm `E:\switch\Fable II\logs\rex\rex_crash.log` does **not** exist.
- Do not delete the `fable_2_0NN.log` files; the new one will be `041` (or the
  next number - return whatever it is).

## 3. Run - the important part

- Launch `fable_2.nro` from hbmenu with a **full-memory / title-takeover**
  launch, not applet mode.
- Do not press any button. Start a **6-minute timer** the moment the menu
  appears.
- The screen may go quiet, stop updating, or freeze. That is expected and is
  not a reason to stop: leave the console alone for the full 6 minutes.
- The app may exit by itself before the timer ends. If it does, note the time.
- Only after the app exits (or 6 minutes have passed) put the console down and
  copy the logs.
- If the console itself stops responding (HOME does nothing), power-cycle it and
  report that - do not keep waiting.

## 4. Return

1. `sd:/switch/Fable II/logs/` - the whole folder, including the newest
   `fable_2_0NN.log`, `rex/rex_crash.log` and `rex_crash.pre041.log`.
2. `sd:/switch/Fable II/logs/rex/rex_crash.log` if it exists - whole file; any
   block in it is from this run.
3. Time to exit (or "still running at 6:00"), and whether the screen was frozen
   or animating at the end.
4. The NRO hash you copied.

## 5. What the result means

The log must contain, near the top:

```
[fable2] build tag: m1-witness-041 (sub_822358A8 GUI null witness armed)
```

If it is not there, the old NRO ran; say so and stop - the rest is not usable.

When the fault fires, the log gains (warn level, flushed at once):

```
[gui-witness] #1 sub_822358A8 r3=0 lr=<caller> r4=.. r5=.. r6=.. r7=..
[gui-witness]   83496920 a=.. b=.. c=.. d=.. e=.. f=.. g=.. h=.. i=..
```

- `lr` names which of the six GUI callers passed the null (table in
  `docs/STATUS.md`).
- `a..i` are the chain loads; `i` is r3. `h` valid with `i = 0` means the object
  exists and `+0x64` was never written; an earlier zero names the missing link.
- A new block in `rex_crash.log` with `far ... 0x24` confirms the same fault.
- **No witness line after 6 full minutes is a valid result**: it means the fault
  did not fire in that window. Return the log anyway and say the app's state.
  Do not rerun before reporting.
