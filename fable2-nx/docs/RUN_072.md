# run-072 - hook every exit path; verify the guest-visible short-read status

## What run 071 proved

- **No GPU error**: death-watch at presents 32/64/96/128/160 all `gpu error
  state=no`. (Blind spot noted: the check ran before the kick; a fault on the
  kicked frame could be missed if the OS kill lands before the next present -
  run-072 adds checks at frame submit and right after the kick.)
- **No hook fired**: no rex_exit_marker.log entry, no new crash block, no
  terminate/abort record. The process does not leave through exit()/abort()/
  std::terminate/CPU-exception.
- **Death time FIXED ~9.3 s** with or without uploads. Uploads start ~8.4 s
  because the guest streams GUI assets then - they are a SYMPTOM of the guest
  progress point, not the cause. Stop treating them as the killer.
- rex_actions.log dominated by `io read short/fail ... st=0` - legal EOF short
  reads (SUCCESS + real count), e.g. book.babel off=2629632 req=2048 got=1815.

## Host-side verification of the short-read chain (before this run)

- `HostPathFile::LeerDirecta`: a short read returns **X_STATUS_SUCCESS + the
  real count**; END_OF_FILE only when the FIRST read truly fails (0 bytes).
- `NtReadFile`: writes `iosb.status = result`, `iosb.information = bytes_read`;
  for async files (the game opens them that way) queues the completion APC and
  returns PENDING; signals the event. The chain LOOKS correct - this run logs
  what the guest actually receives, per read, to confirm on hardware.
- Static exit-path audit: the SDK's only exit() sites (XamShowDirtyDiscErrorUI,
  HalReturnToFirmware) log ERROR first - never seen; xmemory's `_Exit(4)` needs
  2000 heap failures and logs errors - never seen; OnClosing/__libnx_exit logs
  INFO + flush - never seen; TerminateTitle only ends guest threads. So the
  death is a path that bypasses ALL logging (direct svcExitProcess/_exit) or an
  external OS kill. The wraps below catch the former; the witnesses catch the
  latter's GPU variant.

## What this build changes (instrumentation; no GPU behaviour change)

1. **Linker --wrap hooks for EVERY deliberate exit path**: `svcExitProcess`,
   `__libnx_exit`, `_exit`, `_Exit`, `exit`, `__assert_func`
   (`sdk/src/ui/switch_exit_wraps.c`, flags in `rexglue_switch.cmake`). Each
   wrapper writes the crash block FIRST - build tag, CALLER stack (frame chain
   + stack scan), last-host-action ring, per-boot marker - then calls the real
   function. `--wrap` routes every reference at final link, including the ones
   inside libnx/newlib/deko3d. Whatever ends the process now names its site.
2. **Guest-visible short-read status**: `[io] SHORT READ guest-visible: ...
   iosb.status=... iosb.info=... returned=... apc_queued=... ev_signaled=...`
   (first 16), plus EVERY read completion in the host-action ring
   (`read '<path>' off=... req=... got=... iosb=... ret=... apc=...`).
3. **death-watch dumps the last 3 host actions into the MAIN log** every 32
   presents - a silent OS kill fires no hook, so this leaves the last
   reads/uploads named even when nothing else writes.
4. **GPU error witnesses at frame submit (Flush) and right after the present
   kick** - closes the single-thread blind spot from run 071.
