# run-077 - the prologue list: uploads outside the render pass

## What run 076 proved

- **2x2: A=B=C=D=PASS** - "both legal in isolation - fault is frame context".
  The copy primitive, both staging kinds (0x9 CpuUncached|GpuCached, no flush),
  the texture-cache images (0x800, GpuCached|Image, offset 0) and the
  descriptors are ALL innocent. Something about being inside the frame's draw
  list (render targets bound / open 3D state, or aliasing with bound textures)
  kills the channel.
- **SOURCE staging all-zero CPU-side** ("0 non-zero of first 4096") - the guest
  mirror pages the upload reads are EMPTY. A separate F1/M3 source-data
  problem: even a perfect copy lands zeros until the guest's texture data
  reaches shared memory.
- Correction recorded in STATUS.md: the 074/075 "copies landed zeros" verdicts
  were measurement artefacts (probe checked 0x5A against guest data);
  "width%64 is the discriminator" retracted as the fault cause.

## The structural change (one)

**Uploads ride a dedicated copy-only PROLOGUE list**, submitted and kicked
immediately BEFORE the frame's draw list:

1. During frame recording, every `CopyBufferToImage` (+ Full barrier,
   Image|Descriptors|L2 invalidate) is recorded into the texture cache's own
   `upload_command_buffer_` - **no draws, no render targets, no texture binds**
   in that list. Nothing to unbind: a fresh deko3d list binds nothing.
2. `IssueSwap` calls `texture_cache_->SubmitUploadPrologue()` BEFORE
   `render_target_cache_->Flush()`: submit + signalFence + **flush** (kick), so
   the copies execute ahead of the draw list; queue order then orders them
   before every draw of the frame.
3. Kept unchanged: one-frame sampling delay, staging cohort pinning, depth
   skip, w64/h8 alignment, copies-only probe (first 4), 2x2 matrix at setup,
   correlation dump, exit hooks, death-watch, guest readback.
4. `deko3d_upload_prologue = false` restores the legacy in-draw-list path (A/B).

New logs: `[upload-prologue] N copy/copies submitted in a copy-only list ...
before frame submit #K`; `[upload] #N ... recorded into the PROLOGUE list`;
**`[upload-src] guest mirror base_page=... first bytes [...] N non-zero of
4096`** - names the empty-mirror source-data problem directly (first 8).

If the prologue ALSO faults: the `[gpu-error]` correlation dump shows the last
prologue/frame/bind actions - the inherited state at submit - naming which of
(bound-RT / aliasing) it is.
