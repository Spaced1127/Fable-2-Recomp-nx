# run-076 - the 2x2: source staging x destination image, known content

## What run 075 showed

Alignment was NOT the cause: 480->512 (%64=0), 240->256, heights 360/184 (%8=0),
flags 0x800, sane layouts - copies STILL land `[00000000]`, fence true, queue
error=no, waitIdle 5 ms. Same fatal error at present #157.

**Probe bug found and fixed:** the old probe checked the readback for `0x5A`,
but the upload staging holds DECODED GUEST DATA - the pattern was never in the
source, so "FAIL - pattern did not land" was meaningless. The probe now reports
non-zero data landed vs all-zero, AND logs the SOURCE staging CPU-side bytes
before submit: if staging is zero on the CPU, the guest mirror pages are empty
and no copy can land pixels - a source-data fault, not a copy fault.

## The 2x2 (this run, at setup, known 0x5A content in BOTH staging kinds)

| cell | source | destination |
|---|---|---|
| A | setup staging (0x5A, 4096x720) | setup image 960x720 RGBA8 (known PASS control) |
| B | setup staging (0x5A) | texture-cache image via REAL CreateTexture (480x360 -> aligned 512x360) |
| C | texture-path staging (0x5A, upload-path size/flags) | setup image (rect 960x360) |
| D | texture-path staging (0x5A) | texture-cache image (512x360) |

One line per cell: staging `DkMemBlockFlags` (0x9 = CpuUncached|GpuCached),
size, gpu addr, flush policy (none - uncached write-through; the upload path
calls FlushCpuRange only when the cached-staging cvar is set), the exact
`DkCopyBuf {addr, rowLength, imageHeight}`, the `DkImageRect`, destination
flags 0x800 / layout-size / align / offset 0 / mem-flags 0x28 (GpuCached|Image),
idle/fence/error, readback bytes, PASS/FAIL. Then a one-line verdict:

- A,B PASS + C,D FAIL -> **SOURCE staging** at fault.
- A,C PASS + B,D FAIL -> **DESTINATION tex-image** at fault (next: full
  DkImageSettings + 2D-engine offset alignment, and a fresh dedicated block).
- all PASS -> both legal in isolation; the fault is the **frame context**.
- mixed -> the per-cell values name it.

Plus the first-upload probe (cell E, real guest data): SOURCE staging CPU-side
bytes + non-zero readback verdict - separates "guest data is zero" from "copy
wrote nothing".

**Strategy frozen until the table is in** (user directive): barrier, one-frame
delay, depth skip, w64/h8 alignment all kept unchanged.
