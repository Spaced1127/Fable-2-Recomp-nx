So the key is the **Albion world root, `Data\Worlds\Albion\`** (template
`Data\Worlds\` + the literal `Albion` at `0x820A6268` + the separator; the dump
shows the tail `ds\Albion\`), and the 4 s is **not** in the key builder - it is
in the four calls `sub_825F3050` makes before it. The registry entry for the
Albion world is absent, the batch is empty, the pass exits, and the draw then
dereferences the null page set.

No producer is named yet, so this run does two things and only one of them
changes behaviour:

1. **FIX (one measured variable):** `sub_822358A8` is no longer called with
   `r3 = 0`. The callee dereferences r3 unconditionally (`lwz r9, 36(r3)` in
   `sub_82235698`), so a null page set has no valid interpretation; skipping the
   call leaves that element's UV rects untouched instead of taking the process
   down. A `[gui-guard] #n skipped ...` line marks every skip.
   This removes the **crash**, not the missing world entry.
2. **Probe (passive):** `[gui-phase]` markers after each of the four setup
   calls localise the 4.0 s, which is the same subsystem that should register
   the world root.
