# run-068 - does that one copy execute? A synchronous answer that cannot lie

Revised 2026-11-18 (fresh session): descriptor **A only**, **CpuUncached
readback**, queue error state logged. Supersedes the A/B/C build
`7370D155...` - same experiment, two corrections that remove its false-verdict
paths. One measured variable per run.

## 1. Why run 067's verdict was not accepted - and the mechanism now named

Run 067 submitted only the 960x720 copy and its fence timed out after 1000 ms -
yet the same queue then presented 180 frames and the present fence signalled at
present #1. The summary line ("the copy alone is the killer") was premature and
is retracted: the app **survived** the copy.

Host-side disassembly of the installed `libdeko3d.a` (`dk_queue.o`, `dk_fence.o`)
and libnx `gpu_channel.o` - byte-identical (MD5) to the WSL toolchain the NRO
links - names the mechanism:

- `submitCommands` and `signalFence` only **append GPFIFO entries** to a
  2048-entry pending batch; neither rings the doorbell.
- The kickoff (`nvGpuChannelKickoff`) fires only from `Queue::flush`, which the
  frame loop reaches via **`presentImage`**, and from **`waitIdle`**
  (= signalFence + flush + wait).
- So every standalone copy probe (058 boot, 065 a-d, 067 bisect) timed out with
  the entries **never fetched**. 065's copy-diag ran on the presenting thread:
  its four 250 ms waits ARE the present #179 (19.016) -> #180 (20.312) gap, and
  #180's kick executed the whole burst *after* the readbacks. 067's wait ended
  52.255; present #1 kicked 52.313 - the copy rode that kick and was harmless.
- Fences are a **monotonic per-channel semaphore** (`wait` = `*payload >=
  expected`): a signalling present fence retroactively satisfies every earlier
  fence on queue 0x1. The 067 copy fence would read SIGNALLED if re-polled after
  present #1; it never was.

This is a host-side finding, **unverified on hardware until this run**. It
retracts "fence primitive dead" (058) and "standalone submit path dead" (065) as
hardware claims. `waitIdle` is the trustworthy witness precisely because it
flushes/kicks.

## 2. What this build does: stop trusting the fence

At setup only, for descriptor **A** (rows - what the port passes now):

1. record the copy into a **fresh list**, and log the **list handle**, the
   **command buffer it came from** and the **source GPU address/pitch**;
2. submit it, log the fence state (`wait(0)`) **before** and **after** a
   `dkQueueWaitIdle` that runs in a thread with a 2 s observation window (the API
   has no timeout of its own, so the window is ours and the log always continues);
   the after-line also prints `dkQueueIsInErrorState` (channel fault witness);
3. read 64x64 of the destination back and print the pixels. The readback block
   is **CpuUncached**: with CpuCached the CPU would read its own dirty 0xAA
   pre-fill lines even when the GPU wrote the pattern to DRAM - a fake DROPPED.
   This deko3d has no CPU-cache invalidate API, so uncached is the only coherent
   readback;
4. verdict **EXECUTED** (pattern read back) / **DROPPED** (WaitIdle returned, the
   destination is untouched) / **WEDGED** (WaitIdle never returned; stops there).

Descriptors B (imageHeight = total bytes) and C (tight 0/0) stay in the code
behind `deko3d_copy_sync_extra = false`. B is the run-060 OS-kill DMA (~12 GB of
out-of-bounds source reads) **if it ever executes**, and C answers nothing once
A has decided. They are a later A/B, not this run.

| attempt | rowLength | imageHeight | status |
|---|---|---|---|
| A | 4096 | 720 | **this run** - rows, what the port passes now |
| B | 4096 | 2949120 | opt-in - total bytes, the old reading (can kill) |
| C | 0 | 0 | opt-in - tightly packed, deko3d samples' canonical form |

## 3. What each outcome means

- **EXECUTED** -> the copy is legal with the port's descriptor; the kickoff
  finding is confirmed. Run 066's ~250 ms death is then the draw that samples
  the uploaded image (or uploads #2-4 / staging reuse), and run-069 bisects the
  descriptor/sampler path with a 64x64 render target.
- **DROPPED** -> the command never reaches the GPU even though `WaitIdle`
  returns and kicks: the list/submit pairing or the command memory is being
  discarded. Chase `finishList`/`addMemory` and run 066's `[submit]` addresses.
- **WEDGED** -> a real wedge; only then is copy legality (flags, tiling,
  tile-aligned rect, units) the thing to pursue.

Nothing else changes in this build: guest path, present blit and UI untouched;
`deko3d_copy_bisect = false`, `deko3d_upload_validate` armed but non-blocking.
