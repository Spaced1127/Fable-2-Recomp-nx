# run-074 - the decisive copies-only frame; flags/extent table per shape

## What run 073 proved

- Barrier applied and logged: `DkBarrier_Full(4) invalidate=0x15`
  (Image|Descriptors|L2Cache). One-frame sampling delay active. **Fault
  unchanged**: `[gpu-error] right after present #158 kick`; frame submit #157
  carried 3 upload copies and - because of the delay - NO draw sampled the new
  images. So the fault is not read-while-write and not a missing barrier: **the
  copy command itself faults the channel on the texture-cache images.**

| SETUP-TEST 960x720 RGBA8 (PASSED) | 28 | **0x800** | 2949120 | 512 | pitch 4096, height 720 (%8=0) |
| tex-cache 960x720 ZF32_X24S8 | 45 | **0x800** | 5898240 | 65536 | depth - skipped, never bound |

**Usage2DEngine (0x800) IS present on every texture-cache image** - the
"missing flag" hypothesis is disproved by the logged values; offsets are 0 and
mem == layout-size (aligned). The differences that remain: the **RGB10A2
format** (never tested in isolation) and **height 180, not a multiple of 8**
(the block-linear GOB height) - every proven-good copy had height %8 == 0
(720, 360). A block-linear destination whose copy rect height is not
GOB-aligned faults the copy engine exactly like this. The probe below
discriminates format vs alignment vs extent, per shape, with values.

## What this build does (one question)

1. **Copies-only probe** (`deko3d_upload_sync_probe = true`): the first 4
   uploads (the depth skip doesn't count) submit **ONLY the copy** into a
   dedicated cmdbuf - no draws, no sampling - then flush, bounded `waitIdle`
   (2 s window), fence state, queue error state, and a 64x64 CpuUncached
   readback. Per shape:
   `[upload-sync] probe #N WxH xenosF->dekoF: image flags=0x800 layout-size=...
   align=... gpu=... offset=0 | rect=WxH (height%8=.. width%64=..) | src
   rowLength=... imageHeight=... extent=... staging=... | layout>=rect-bytes:
   yes/NO` then `verdict PASS/FAIL-WEDGED/FAIL`.
2. **Setup-test reference** logged in the same `[tex-image]` format
   (`SETUP-TEST created 960x720 ... flags=0x800 layout-size=2949120 align=512`)
   so the table compares directly.
3. **Guest-output readback gated OFF** (`deko3d_guest_readback = false`) - its
   #150 submit lands near the upload batch; one question per run.
4. Kept: barrier + invalidate, one-frame delay, depth-never-bind, staging
   cohorts, correlation dump at the error witness, exit hooks, death-watch.

## Acceptance / how to read the result

- **A probe FAIL-WEDGED** -> that shape's copy is illegal on that image; the
  table above the verdict carries the values (flags/layout/align/extent/%8).
  Fix belongs in the image creation or the copy descriptor for that shape
  (e.g. pad the copy rect/layout to GOB alignment, or convert RGB10A2).
- **All probes PASS but the frame still faults** -> the copies are legal in
  isolation; the fault is the frame context (interaction with the frame's
  other commands). Next: dump the full DkImageDescriptor/DkSampler of the
  first draw that binds a freshly written image.
- **All probes PASS and survival past 60 s** -> the synchronous execution
  order itself was the fix; run-075 restores the frame-list path with the
  probe-proven shapes and re-enables the guest readback.
