## Why uploads

Run 042 skipped every draw and the app still died at the same ~9 s terminus
while frames advanced (frame 127, `drew 0`), so the draw path is exonerated. The
remaining discriminator in the full history is texture uploads:

- **uploads enabled**: runs 028, 036, 037 survived past 9 s (036 for 272 s, 037
  for 47 s), with `fence wait timed out for texture upload after 5000 ms` and
  `texture upload stalled`, then continued with the placeholder.
- **uploads disabled**: runs 038-042 all die at 8-9 s, no report, no violation.

Run 043 turns uploads back on. It is a diagnostic: the known copy wedge returns,
but it is bounded by the 5 s upload fence and `upload_stopped_`, exactly as in
036/037. If the app survives past ~15 s, the no-upload path is the gate and the
menu continues toward the null-deref, where the witness is armed.

One more fact from 042's log: the last swap is swap 2 at 05:52:06.167, and the app
then runs ~6.8 s with no present (frames to 127, draws to the death). The white
picture was the last presented frame held on screen. The fatal operation is in that
non-present phase - render target creation, clears, copies/resolves - which is also
where the upload path changes the GPU state.
