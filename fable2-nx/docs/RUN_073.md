# run-073 - barrier + one-frame sampling delay; correlate the fault with one image

## What run 072 proved

- **Short reads are CORRECT and CLOSED**: every one `iosb.status=0x0`,
  `iosb.info=actual bytes`, `returned=0x103` (PENDING), APC queued. Stop
  re-testing; the per-read log/ring flood is removed (failures only now).
- **No exit hook fired** - the death is not a deliberate exit call.
- **The GPU error witness fired**: `[gpu-error] queue in ERROR state right
  after present #157 kick`. `[frame] submit #156 carried 3 upload copy/copies`
  (480x360 RGBA8 deko 28 + 2x 240x180 RGB10A2 deko 52). death-watch at #128 and
  earlier: `gpu error state=no`. **The error is born exactly at the kick of the
  frame that carried the copies** - the in-frame upload work faults the GPU
  asynchronously; the OS then kills the process (~9.4 s, 157 presents).
- The isolated setup copy worked because nothing sampled its destination in
  the same submit. In-frame, the list contains copyBufferToImage into image X
  and draws that sample X.

## Barrier note (this deko3d)

There is **no `DkBarrier_2DTo3D`** in the installed deko3d: the enum is
None(0)/Tiles(1)/Fragments(2)/Primitives(3)/Full(4). `DkBarrier_Full` =
"completes the processing of all previous commands while disabling command
list prefetch" - the strongest ordering available, and it was ALREADY recorded
after every copy. Run-073 strengthens the invalidate mask to
`Image | Descriptors | L2Cache` (0x13) and logs the values once
(`[upload] barrier after copy: DkBarrier_Full(4) invalidate=0x13`).

## Second hole found and closed

Depth-skipped textures (xenos 23 -> ZF32_X24S8) were still CREATED and BOUND -
a draw sampling a depth image as colour is itself a fault candidate. Run-073:
a depth-skipped image is **never bound** (placeholder forever).

## What this build changes

1. **One-frame sampling delay** (`deko3d_upload_defer_sampling = true`): each
   uploaded image records the cohort = the frame submit carrying its copy;
   `GetBoundTexture` binds it only when `FrameSubmitEpoch() >= cohort` (the
   copy's frame has been submitted and kicked; the in-order queue has executed
   it before the next frame's draws run). cohort 0 = never uploaded ->
   placeholder. This rules out read-while-write on the same submit.
2. **Barrier invalidate strengthened** (above), frame path and standalone path.
3. **Probe OFF by default** (`deko3d_upload_probe_frame = false`) so its own 2D
   readback cannot confound the test; re-enable in run-074 to prove landing.
4. **Frame/image correlation at the error witness**: the post-kick `[gpu-error]`
   now dumps the last 10 host actions - upload records, `[tex-image] created
   ... flags/layout-size/align/gpu-addr` (full creation parameters, first 12),
   and per-draw `bind tex gpu=... fmt=... WxH submit-epoch=...` - so the fault
   correlates with one specific image.
5. Short-read flood removed; only genuine `XFAILED` reads logged.

Kept: staging cohorts, depth skip, exit wraps/markers, guest-readback #30/#150,
censuses, death-watch (with last-actions dump).
