# run-075 - the alignment fix: width%64=0 / height%8=0 upload destinations

## What run 074 proved (the discriminator)

Copies-only probes, all flags=0x800, fence signalled, queue error=no:

| shape | fmt | layout | width%64 | height%8 | verdict |
|---|---|---|---|---|---|
| SETUP-TEST 960x720 | 28 RGBA8 | 2949120 | **0** | 0 | **PASS [5A5A5A5A]** |
| probe #1 480x360 | 28 RGBA8 | 737280 | **32** | 0 | **FAIL [00000000]** |
| probe #2/#3 240x180 | 52 RGB10A2 | 245760 | **48** | 4 | **FAIL [00000000]** |

**WIDTH alignment to 64 pixels is the discriminator** - probe #1 has
height%8=0 and still fails, so height is not it. Every width%64==0 copy lands
the pattern; every other width lands ZERO bytes in isolation and faults the
channel in-frame (the ~9.4 s death). This is the deko3d tiled-layout
requirement for a 2D-engine destination, and it explains why the 960-wide
setup test always passed while every real texture failed.

## The fix (where it is applied)

1. **`TextureImpl::Initialize`**: the image LAYOUT is created at
   `aligned_width = (w+63)&~63`, `aligned_height = (h+7)&~7` (2D images).
   `width_`/`height_` stay LOGICAL - `GetBoundTexture` still returns the real
   240/480 for the descriptor and UV mapping. `[tex-image]` logs both.
2. **Upload staging** (`LoadTextureDataFromResidentMemoryImpl`):
   `source_pitch = align4096(aligned_row_bytes)`,
   `staging_bytes = source_pitch * aligned_blocks_high`. The decode/untile
   still fills the LOGICAL rows/width; the existing memset zeroes the padding
   tail and the extra aligned rows, so the staging contains valid padded rows.
3. **Copy descriptor** (all three paths: copies-only probe, frame list,
   standalone fallback): `rect = aligned_w x aligned_h`,
   `imageHeight = aligned_blocks_high`, `rowLength = source_pitch`.
4. **Copies-only probe re-runs first** (first 4 uploads): expect PASS with the
   pattern for 480x360 and 240x180; only then does the normal frame-list path
   take over (uploads 5+). The flags/extent table stays in the log.
5. **Guest-output readback re-enabled** (present 30/150) - with survival it is
   the F1 evidence (does the fnv1a start to differ).

Kept: Full barrier + Image|Descriptors|L2 invalidate, one-frame sampling delay,
depth-never-bind, staging cohorts, correlation dump, exit hooks, death-watch.

**Known caveat (M3, not chased today):** sampling a padded image with the
guest's UVs reads the padding tail as texture (480/512 scale). The correct
logical/aligned UV scale belongs in the DKSH shader path (M3 texture
correctness); today's question is the fault and survival.
