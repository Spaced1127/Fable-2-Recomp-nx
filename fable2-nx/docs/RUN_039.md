# run-039 - M1 witness run

Diagnostic run. It changes **no setting and no game behaviour**: the build only
adds a passive logger at the function whose argument is null. Its job is to name
the caller and the chain link that is zero, so the producer can be fixed at the
source instead of guessed.

Build: SHA-256 `0B0D5CBFAA043659E0B8B0CD8EDC2DCD876F2790842B9BE548FA0E48BAE376E6`
(`stage\switch\Fable II\fable_2.nro`, 99,006,661 bytes).

## 1. Copy to the SD

Close hbmenu's file browser and any running app first. Replace `E:` with your SD
drive letter. Copy only the three files - never mirror the folder, or the logs
and saves already on the card would be deleted:

```powershell
$src = "H:\Projects\Fable2Port\stage\switch\Fable II"
$dst = "E:\switch\Fable II"
Copy-Item "$src\fable_2.nro"          "$dst\fable_2.nro"          -Force
Copy-Item "$src\fable_2.toml"         "$dst\fable_2.toml"         -Force
Copy-Item "$src\fable2_config.toml"   "$dst\fable2_config.toml"   -Force
```

`Game_files` is unchanged from run 038 and stays as it is. Verify the copy:

```powershell
(Get-FileHash "E:\switch\Fable II\fable_2.nro" -Algorithm SHA256).Hash
# must be 0B0D5CBFAA043659E0B8B0CD8EDC2DCD876F2790842B9BE548FA0E48BAE376E6
```

## 2. Fresh crash report - do this before launching

`sd:/switch/Fable II/logs/rex/rex_crash.log` is **append-only and is never
overwritten**. A stale report has misled this project twice. Before the run:

- If `E:\switch\Fable II\logs\rex\rex_crash.log` exists, rename it to
  `rex_crash.pre039.log` (keep it - it is the old record).
- Confirm `E:\switch\Fable II\logs\rex\rex_crash.log` does **not** exist.
- Do **not** delete the `fable_2_0NN.log` files: log numbering continues, so the
  new file should be `fable_2_039.log`. If it is not 039, return it anyway and
  say which number it is.

## 3. Run

- Launch `fable_2.nro` from hbmenu with a **full-memory / title-takeover**
  launch (not applet mode).
- Leave the game at the main menu. **Do not press any button** - the crash has
  fired while the menu is idle/drawing, and input changes the path.
- Wait until the app exits by itself, or **6 minutes**, whichever comes first.
- Note: the time it took, what was on screen at the end (black / white / test
  pattern / frozen frame), and whether the app closed cleanly or the console
  froze (a frozen console means power-cycle it).

**Copy the logs only after the app has exited.** Run 039 showed why: the log was
copied 7 s before the crash report was written, so the final lines - the ones
this run exists to capture - were missing. The game can hang for ~40 s after its
last ordinary log line and then crash, and the witness lines are written at that
moment.

## 5. What the result means

Look for this in the newest log:

```
[gui-witness] #1 sub_822358A8 r3=0 lr=<hex> r4=.. r5=.. r6=.. r7=..
[gui-witness]   83496920 a=.. b=.. c=.. d=.. e=.. f=.. g=.. h=.. i=..
```

- `lr` tells which of the six GUI callers passed the null (0x822050C4,
  0x82390590, 0x82457B7C, 0x82459908, 0x82749BEC or 0x82781734 - names in
  `docs/STATUS.md`).
- `a..i` are the successive loads; `i` is r3. If `h` is a valid pointer and
  `i = 0`, the object exists and its `+0x64` field was never written (fix at the
  writer). If an earlier letter is 0, the log names the first missing link, i.e.
  the subsystem that failed to initialise.
- If the violation appears **without** a `[gui-witness]` line, the crash came
  from a path that does not call `sub_822358A8`, and the next run must widen the
  witness - say so in the report.
- If no violation appears at all, M1 did not reproduce this run; return the log
  anyway and say how long the menu stayed alive.

## 6. If the build does not boot

This NRO is **not hardware-verified**. If it does not reach the menu (no
`[deko3d]` present lines, or it dies before the first frame), do not spend time
debugging on the console:

```powershell
Copy-Item "H:\Projects\Fable2Port\stage\backup\fable_2_run038_proven.nro" "E:\switch\Fable II\fable_2.nro" -Force
```

That restores the run-038 build (SHA-256
`6D20ECDC88CB03C22AA9FDEA026314466FEACCCC6D8D435BEAB103BAB9AB0C30`), which booted
and ran the menu. Report the failure with whatever log the bad build wrote - the
witness is diagnostic only and a boot failure is a bug in it, not in the game.
